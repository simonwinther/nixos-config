# Recovery and rollback

Before erasure, abort by shutting down the live USB and booting the unchanged old desktop. Keep the backup and laptop intact. After erasure, restoring the old OS requires the tested disk image or file backup and its bootloader/encryption recovery material; a Nix generation cannot reconstruct an erased Arch installation.

For a failed NixOS update, select an older generation in systemd-boot. From a working TTY, use `sudo nixos-rebuild switch --rollback` to return software/system configuration, then inspect Home Manager's activation log and rebuild the intended flake revision. Restoring a Nix generation does not undo edits to home files, browser/database migrations, Flatpak updates, or secrets. Use independent backups or a reviewed Btrfs snapshot for those, with affected applications stopped.

The `desktop-recovery` flake configuration uses the same selected disk and storage layout with a console-oriented system and no personal graphical environment. Build it before installing the full workstation. If the GUI fails but a TTY works, build/switch the recovery configuration there, inspect `journalctl -b`, and rebuild the workstation after fixing its driver or user configuration. Keep at least one tested older boot generation; garbage collection is not scheduled automatically.

If nothing boots, use a known-good NixOS USB in UEFI mode. Identify the target by serial and size. Open the existing LUKS container with `cryptsetup open` and mount its existing Btrfs subvolumes and ESP at `/mnt`, matching the declarative layout. Never use Disko's destroy/format modes for recovery. Use the live system's `lsblk`, `blkid`, `cryptsetup status`, and `btrfs subvolume list` to inspect before mounting. Restore the repository from independent storage, enter with `nixos-enter --root /mnt`, and rebuild/repair the bootloader from the last tested configuration. Use the correct host; do not regenerate a different disk layout over the existing installation.

If the LUKS header is damaged, preserve an image of the damaged disk before considering header restoration. Use the matching encrypted header backup and verified passphrase; never restore another disk's header. If the passphrase and all valid keys are lost, neither Nix nor a header backup decrypts the data.

For a bad desktop theme or monitor toggle, switch to TTY and move only `~/.local/state/desktop/state.json` and `~/.local/state/desktop/toggles/hypr/` aside, retaining them for diagnosis. The next session falls back to the declared theme and host monitor configuration. Do not delete personal data or rewrite the read-only configuration links. Use `journalctl --user -b -u desktop-prepare -u desktop-waybar -u desktop-walker` and `hyprctl configerrors` inside the target session.

For data recovery, stop the relevant applications and restore to a separate directory first. Compare content, ownership, ACLs and xattrs, then restore selected data. Snapper's `/home` snapshots reside on the same physical disk and do not survive disk failure or replacement. Test Restic decryption and sample restoration periodically, using recovery credentials that do not depend on the failed machine.
